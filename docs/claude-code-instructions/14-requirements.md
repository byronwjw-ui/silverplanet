# 第十四部分 · 具体要求 & 验收标准

## 代码要求

1. **所有代码必须完整、可运行**。不要用 TODO 或"此处省略"或占位实现。
2. **每个组件单独一个文件**，命名清晰，PascalCase。
3. **API 路由需要错误处理**，返回合适的 HTTP 状态码和错误信息（参考模块 09 的统一响应格式）。
4. **类型安全**：所有函数参数、返回值、组件 props 必须有 TypeScript 类型。
5. **关键操作（支付、删除、审核）需要二次确认**。

## 老人端 UI 要求

1. 所有文字使用 `elderly-*` 字号
2. 背景纯白，文字纯黑，按钮亮橙
3. 按钮高度不低于 60px
4. 触摸目标不小于 48x48 px
5. 高对比度模式（WCAG AAA 级别）
6. 不使用复杂动画
7. 不使用浮层模态框（用全屏页面替代）
8. 错误提示用大字 + 红色，不用 toast 一闪而过

## 管理后台 UI 要求

1. 标准的深色 sidebar + 浅色内容区
2. 表格支持排序、筛选、分页
3. 重要操作有 loading 状态
4. 成功/失败用 toast 提示
5. 表单字段有清晰的错误提示

## 移动端要求

- 移动端优先设计
- 老人端页面在手机上必须完美显示
- 横竖屏都要适配
- 兼容 iOS Safari 14+ 和 Android Chrome 90+
- 支持 PWA "添加到桌面"

## 安全要求

1. 所有用户输入需要做基本的安全校验（XSS、SQL注入防护）
2. 密码加盐哈希（bcrypt）
3. JWT token 有效期 7 天
4. API 路由验证 session 和角色
5. 敏感操作（修改密码、删除账户）需要重新验证
6. 老人的对话记录加密存储（数据库列级加密）

## 性能要求

1. 落地页 FCP < 1.5s, LCP < 2.5s
2. AI 对话响应时间：从用户说完到 AI 开始播放语音 < 5 秒
3. 图片使用 next/image 自动优化
4. 数据库查询有合适的索引

## 数据库要求

1. 使用 Prisma，所有查询需要考虑软删除（deletedAt）
2. 关键字段必须有索引
3. 字符串字段需要合理的长度限制
4. 重要操作记录审计日志

## 降级策略

1. 语音功能如果配置了 API Key 就用云端服务，否则降级到浏览器 Web Speech API
2. 微信登录如果没配置就只允许手机号登录
3. 微信支付如果没配置就用手动确认模式

## 测试要求

每个阶段完成后：
1. 跑通主流程（手动测试）
2. 写关键业务逻辑的单元测试
3. 用 Playwright 写 1-2 个 E2E 测试覆盖核心场景

## 提交规范

使用 Conventional Commits：
- feat: 新功能
- fix: 修 bug
- docs: 文档
- style: 格式
- refactor: 重构
- test: 测试
- chore: 杂项

每个 commit 只做一件事，commit message 用中文或英文都可以但要清晰。

## 阶段交付物

每完成一个阶段，给出：
1. 已实现的功能清单
2. 如何手动测试每个功能
3. 已知问题和限制
4. 下一阶段计划
